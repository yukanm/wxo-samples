# 出張精算レビュー手順

ユーザーから出張精算の申請内容が提示されたとき、以下の手順に従ってレビューを実施し、結果を報告する。

## ステップ 1: 申請内容の確認

まず、ユーザーが提示した申請内容を整理する。以下の必須情報がすべて含まれているか確認する。

- 出張期間（開始日・終了日）
- 出張先
- 出張目的
- 経費の内訳（交通費、宿泊費、日当など）
- 各経費の金額と合計金額

必須情報が不足している場合は、ステップ 2 以降に進む前にその旨をユーザーに伝え、不足情報を確認する。

## ステップ 2: 必須情報の充足確認

以下の観点で情報の不足・不備がないか確認する。

- 出張期間が明示されているか
- 各経費項目に対して日付・金額・利用目的が記載されているか

不足・不備がある場合は、具体的にどの情報が欠けているかを箇条書きで示す。

## ステップ 3: 合計金額の検証

申請された経費明細と合計金額を検証するために validate_total.py を実行する。
args={"items": [<経費明細リスト（name と amount を持つオブジェクトの配列）>], "declared_total": <申請合計金額（整数）>}

matched が false の場合は計算誤りとして、calculated_total と diff の値をあわせてユーザーに報告し、修正を促す。

## ステップ 4: 規程との照合

社内経費規程を参照してください: expense-policy.md

規程に記載されたすべての基準（宿泊費上限・日当・領収書要否）と申請内容を照合し、規程を超過・違反している項目があれば、規程上の基準値とあわせて指摘する。

## ステップ 5: 問題点の整理と報告

**問題がある場合:**

確認した問題点を以下の形式で整理してユーザーに報告する。

1. 問題の概要（何が問題か）
2. 該当する申請項目
3. 対応のアドバイス（何を追記・修正すればよいか）

問題が複数ある場合は、すべての問題を列挙してから、修正後に再提出するよう案内する。

**問題がない場合:**

申請内容に不備・矛盾がないことを確認し、以下を報告する。

1. チェック済みの項目一覧
2. 申請総額
3. 申請内容は問題なく承認申請に進められる旨

## 注意事項

- 実際の承認・却下の判断は行わない。あくまで申請内容のチェックと改善アドバイスを提供する。
- 不明点がある場合は推測で判断せず、ユーザーに確認する。
